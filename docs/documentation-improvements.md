# Documentation Improvement Suggestions

These are documentation-only improvements. No application code changes.

---

## 1. Add a `CONTRIBUTING.md`

Even for a solo portfolio project, a `CONTRIBUTING.md` signals professionalism to recruiters.

Suggested content:
- How to set up the dev environment
- Branch naming convention (`feature/`, `fix/`, `docs/`)
- How to run tests before submitting a PR
- Code style notes (PEP 8 for Python, ESLint for JS)

## 7. Add API documentation with `drf-spectacular` (optional)

Install `drf-spectacular` to auto-generate an OpenAPI 3.0 spec and a Swagger UI at `/api/schema/swagger-ui/`. This is a one-line addition to `settings.py` and `urls.py` and makes the API immediately explorable by anyone viewing the project.

```bash
pip install drf-spectacular
```

Then add to `settings.py`:
```python
INSTALLED_APPS = [..., 'drf_spectacular']
REST_FRAMEWORK = {
    'DEFAULT_SCHEMA_CLASS': 'drf_spectacular.openapi.AutoSchema',
}
```

And to `urls.py`:
```python
from drf_spectacular.views import SpectacularAPIView, SpectacularSwaggerView
urlpatterns += [
    path('api/schema/', SpectacularAPIView.as_view(), name='schema'),
    path('api/docs/', SpectacularSwaggerView.as_view(url_name='schema'), name='swagger-ui'),
]
```

This is a documentation change, not a functional one.
